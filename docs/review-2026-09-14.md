# Daily Workspace review — 14 September 2026

Reviewed the current committed project, focusing on Firefox packaging, documentation, and data handling. The worktree was clean before the homepage was added. This is a focused review, not a complete security or Firefox compatibility audit.

## Findings

### P1 — Firefox's no-data declaration conflicts with outbound data

`scripts/build-firefox.mjs:45` declares `data_collection_permissions.required: ['none']`, and its preceding comment claims the extension sends no data anywhere. Weather requests transmit latitude and longitude to Open-Meteo and BigDataCloud (`src/components/cards/WeatherCard.tsx`). Search suggestions transmit typed queries, including to Wikipedia when the engine's host permission is absent (`src/lib/searchSuggestions.ts`). Firefox icon fallback sends website URLs to Google's icon service (`src/components/ShortcutIcon.tsx`, `src/lib/storage.ts`).

Having no first-party server does not make these transmissions local. Mozilla's current guidance defines transmission as data handled outside the add-on or local browser and reserves `none` for add-ons that do not collect or transmit data. Reconcile the actual network flows, manifest data categories, consent behavior, and README privacy claims before submission. Optional flows need permission checks and handling when consent is declined or revoked; changing the manifest alone is insufficient. Source: [Mozilla's built-in data consent documentation](https://extensionworkshop.com/documentation/develop/firefox-builtin-data-consent/).

### P1 — Backup import clears user data before validating the backup schema

`src/components/BackupRestorePanel.tsx:37` accepts any non-array JSON object. Lines 49–50 then clear all local storage and write that object. A syntactically valid file such as `{"settings":{"cardOrder":null}}` passes this check, erases saved records after confirmation, and supplies a value that crashes the spread operation in `src/components/DashboardGrid.tsx:22`. An unrelated JSON object or empty object also qualifies as a backup.

Validate known keys, settings fields, array entries, and URLs before enabling import. Preserve a recovery snapshot and handle failed writes instead of deleting all existing data first. This issue predates the Firefox packaging change but remains relevant to release readiness.
